용도별로 보면

여섯 가지 작업 유형마다 무엇이 맞고 무엇이 안 맞는지를 정리했다. 위 필터 칩과 같은 분류다.

a리버스 엔지니어링 · 바이너리 분석

1순위 GhidraMCP — 무료이고 PyGhidra 헤드리스 모드가 헤드리스 환경과 정확히 맞는다. 유료 IDA가 이미 있으면 IDA Pro MCP(단, 공식 Hex-Rays 서버도 검토).

REA는 바이너리·APK·Electron·.NET을 한 도구로 노리는 방향이 정확하지만, 스타 급증 이력 때문에 샌드박스 시험 후 판단. 보조로 Filesystem(샘플 폴더 한정) + Git(노트·스크립트). Desktop Commander는 셸 위험만 더하고 RE 이득이 없어 제외.

b교사 — 문서 · PDF · 과제 데이터

기본은 Filesystem(반 폴더로 한정) + Fetch로 무료로 대부분 해결. URL 문서·PDF 파싱은 Firecrawl.

Desktop Commander는 PDF/DOCX/Excel을 직접 읽고 쓰는 유일한 후보라 학습지·성적표에 실제로 유용하지만, 셸 때문에 Docker 격리가 전제(그래서 Tier A). 과제·성적 데이터가 스프레드시트 DB나 Postgres/SQLite에 있으면 MCP Toolbox + 읽기 전용 DB 유저.

c대용량 파일 라이브러리 · NAS · 홈서버

핵심은 Filesystem을 좁게 허용한 루트로 두는 것. 관리해야 할 진짜 위험은 라이브러리 전체에 대한 쓰기 권한이다.

대규모 트리 검색·diff 편집은 Desktop Commander(Docker 격리 한정). Kubernetes MCP는 홈서버가 실제로 k3s/Kubernetes를 돌릴 때만 — 읽기 전용 + Secrets 차단이면 좋은 클러스터 점검 도구가 된다. 미디어·목록 DB는 MCP Toolbox, 설정·dotfile repo는 Git 서버.

d뉴스 · 리서치 브리핑 · 검색 품질

주 검색은 하나만 — 연구형 질문과 조사 에이전트가 강한 Exa, 또는 날짜·도메인 필터와 tavily_research가 있는 뉴스형 Tavily. 실제 기사 본문은 무료 Fetch로 읽는다.

Brave Search는 저렴한 독립 인덱스 교차검증용. Firecrawl은 사이트 전체 크롤·구조화 추출·변경 알림이 필요할 때만. Context7은 라이브러리 문서 전용이라 뉴스 검색기로 쓰면 안 된다.

e메모리 · 세컨드 브레인 · 노트 검색

공식 Memory 서버 — JSONL 파일 하나에 지식그래프를 저장하는 로컬 방식이라 무료·사적·계정 없음이 장점. 평가는 "상황에 따라"(에이전트는 알려준 것만 기억한다).

Obsidian 볼트는 헤드리스 환경에서 mcp-obsidian을 건너뛰고 Filesystem을 볼트 폴더에 직접 거는 게 답이다 — 마크다운은 앱 없이도 검색·편집된다. Notion은 이미 거기에 살고 있을 때만 원격 서버로.

f가격 · 게시판 모니터링 자동화

Playwright MCP 헤드리스 + 격리/임시 프로필이 정답. 접근성 트리 기반이라 결정적이고, 기본이 빈 세션(로그인 없음)인 게 오히려 안전장치다.

단순 페이지 변경 감지라면 Firecrawl Monitor가 브라우저 자체를 대체할 수 있다. Chrome DevTools MCP는 디버깅 도구라 이 용도에 부적합하고, 어떤 브라우저 MCP든 로그인된 일상 프로필에 자동 연결하는 패턴은 피해야 한다.

지금 내 작업에 대입하면

현재 돌고 있는 작업들에 위 후보를 대입한 실전 배치안이다.

GSP 파일 분석

GhidraMCP 추가가 1순위 — 기드라 12.1.4는 이미 설치돼 있어 브리지만 얹으면 된다. REA는 이미 연결해 쓰는 중(읽기 전용 137개만 허용한 상태)이라, 여기에 분석 사본용 Filesystem(샘플 폴더 한정)을 곁들이면 된다.

가격·핫딜·게시판 모니터링

지금 웹 검색 기반으로 도는 감시 작업들은 Playwright MCP(헤드리스·격리 프로필)로 직접 페이지를 읽게 하거나, 단순 변경 감지는 Firecrawl Monitor로 바꾸면 색인 시차 문제가 줄어든다.

매일 아침 신문(JH 뉴스)

검색 품질을 올릴 거면 Exa 또는 Tavily 중 하나 + 본문 읽기용 Fetch 조합. 둘 다 깔 필요는 없고, 뉴스·날짜 필터 비중이 크면 Tavily 쪽이 맞다.

NAS · 대용량 라이브러리 정리

Filesystem을 정리 대상 폴더로만 좁혀 거는 게 핵심. Kubernetes MCP는 NAS가 실제로 컨테이너 클러스터를 돌리는 구조일 때만 의미가 있고, 지금처럼 Docker 단독이면 보류가 맞다.

과제 제출·채점 데이터

제출 데이터가 DB 형태로 쌓이면 MCP Toolbox + 읽기 전용 유저. 문서 파일 자체를 다루는 일은 Filesystem + (필요하면 Docker 격리한) Desktop Commander 조합.

깔지 않아도 되는 것

Notion·Gmail·캘린더·드라이브·텔레그램·패들렛은 이미 커넥터로 연결돼 있어 커뮤니티 MCP를 또 깔 이유가 없다. 검색 서버 4종 동시 설치도 마찬가지 — 중복은 매 턴 컨텍스트 비용으로 돌아온다.

위험한 권한 — 제한 조건표

인기 서버 중에는 설계 자체가 위험한 것들이 있다. 깔 거면 아래 제한을 세트로 적용해야 한다.

서버위험필수 제한
공식 Filesystem 허용 디렉터리 안에서 임의 파일 읽기/쓰기 실행 인자로 좁은 폴더만 전달. 루트(/)나 홈 전체 금지 — 범위는 실행 인자가 곧 보안 설정이다.
Desktop Commander 전체 셸 실행 + 파일 쓰기. README: 가드레일은 "샌드박스가 아니다" Docker 격리 변형 사용, 명령 차단목록 + 허용 디렉터리. 소중한 자격증명이 있는 호스트에 맨몸으로 노출 금지.
Playwright / Chrome DevTools 브라우저 프로필이 로그인된 권한 그대로 행동 가능. DevTools는 사용 통계를 기본 전송 헤드리스 + 격리/임시 프로필, 로그인 세션 금지. Playwright의 --allow-unrestricted-file-access 금지, DevTools는 --no-usage-statistics.
GitHub MCP 이슈/PR 쓰기, Actions 실행, 비공개 repo 읽기 GITHUB_READ_ONLY=1 또는 /readonly 원격 엔드포인트, repo 한정 fine-grained PAT, GITHUB_TOOLSETS 제한.
MCP Toolbox / Supabase 프로덕션 데이터에 쓰기/DDL 포함 임의 SQL 읽기 전용 DB 유저. 범용 실행보다 tools.yaml 사전 정의 쿼리 우선. Supabase는 ?read_only=true&project_ref=로 범위 고정.
Kubernetes MCP pod exec, 리소스 삭제, Helm 설치 TOML read_only = true, 도구셋 제한, Secrets [[denied_resources]], 최소 권한 전용 kubeconfig.
GhidraMCP / IDA MCP / REA 분석 DB 수정 가능. 디버거·런타임 기능은 대상 코드를 실행함 전용 프로젝트 폴더에서 사본을 분석. "대상 실행/디버그" 도구는 코드 실행으로 취급하고, 신뢰 못 할 샘플은 샌드박스에서.
Firecrawl / Fetch 임의 URL 가져오기(SSRF성), 크롤링 크레딧 소모 Fetch는 공개 URL만. Firecrawl은 크롤 깊이·크레딧 상한 설정.

Tier B인기 있어도 건너뛸 것

스타만 보고 깔면 후회하는 부류 — 유지 중단, 중복, 또는 이 환경과 구조적으로 안 맞는 것들.

  • ✕Notion MCP (로컬)★ 4,676. README 스스로 "더 이상 적극 유지되지 않으니 원격 Notion MCP를 쓰라"고 안내한다. 게다가 Notion은 내장 커넥터와 중복. 필요하면 공식 원격 MCP(OAuth)로.
  • ✕mcp-obsidian★ 4,489. Obsidian 데스크톱 앱이 실행 중이어야 동작한다 — 헤드리스 환경과 구조적으로 안 맞는다. 볼트 폴더에 Filesystem을 직접 거는 걸로 대체. 태그된 릴리스도 없다.
  • ✕Sequential Thinking공식 레퍼런스 서버지만, 실사용 후기 작성자들이 "컨텍스트 비용만큼 값을 못 한다"며 제거한 서버. 공식 목록에 있다고 다 깔 필요는 없다.
  • ✕Figma Context MCP (Framelink)★ 16,057. 디렉터리 데이터 기준 약 116일간 커밋이 없어 "인기 있지만 방치됨"으로 분류됐고, 과거 RCE(CVE-2025-15061, v0.6.3에서 패치) 이력도 있다. Figma→코드 작업이 아니면 무관하고, 필요해도 Figma 공식 호스팅 MCP가 우선.
  • ✕아카이브된 구 레퍼런스 서버들구 GitHub·Slack·Postgres·SQLite·Redis·Google Drive/Maps·Puppeteer·Brave 서버는 servers-archived로 이동됐다. 위의 공식 후계(벤더 공식 서버, MCP Toolbox, Playwright, Brave 신 repo)를 쓸 것.
  • ✕Gmail·캘린더·드라이브·Spotify류 커뮤니티 서버대부분 에이전트 플랫폼이 이미 내장 커넥터로 제공하는 기능의 중복이다. 한계 효용이 낮고, 포크를 쓸 거면 마지막 커밋부터 확인할 것.

읽을 때 감안할 것

스타 수의 출처 수준: 조사 시점에 실시간 브라우저가 github.com을 열지 못해, 모든 GitHub 수치는 웹 인덱스로 읽은 repo 페이지 값이다. 방향 판단에는 충분하지만 정확한 오늘 수치와는 차이가 있을 수 있다.

REA의 스타: 370,531★는 조회 당시 GitHub 페이지에 표시된 값 그대로다. 다만 11일간 약 93k→371k라는 증가 속도는 2차 스냅샷들과 맞춰 봐도 유기적 성장으로 보기 어렵고, 실제 사용자 기반인지는 확인되지 않았다.

가격: Context7·Firecrawl·Exa·Tavily·Brave의 요금은 벤더 요금 페이지를 직접 읽은 게 아니라 2026-10월 2차 비교 자료 기준이다(예: Firecrawl Hobby는 연간 $16 / 월간 $19처럼 결제 주기에 따라 다름). 예산을 잡기 전 공식 요금 페이지에서 재확인할 것.

검토했지만 후보에서 뺀 것: Sentry MCP(약 815★, 2차 출처 — Sentry 사용자에게만 해당), Serena, codebase-memory-mcp(한 목록에서 46,159★로 주장됐으나 직접 확인 못 함). 확인이 안 된 수치는 추측으로 채우지 않았다.

생태계 규모 수치(38,336개 repo, 레지스트리 9,652개)도 2차 출처 기준이다.

더 찾을 때 — 목록 자체가 발견 도구

새 서버를 고를 땐 아래 두 awesome 목록이 표준 출발점이다. punkpeye/awesome-mcp-servers(★ 96,785, MIT, 가장 큰 목록)와 wong2/awesome-mcp-servers(★ 4,379, MIT — PR은 더 이상 받지 않고 mcpservers.org로 제출). 어떤 서버든 깔기 전에 확인할 것: 리눅스 지원, 마지막 릴리스·커밋 날짜, 라이선스, 외부로 데이터를 보내는지, 토큰을 요구하는지.
